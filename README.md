# Аналіз гістологічних зображень тканин

Індивідуальний STEM-проєкт на Python. Частина 7: аналіз ядер, LBP,
пакетні метрики, підготовка даних і графіки порівняння. Алгоритми ручні:
готові реалізації OpenCV, skimage чи scipy.ndimage не використовуються.
NumPy — масиви й базові операції; Pillow — введення, виведення й візуалізація.

## Запуск у Windows

Потрібні Python 3.10+ і Tkinter (є у стандартному інсталяторі Python для Windows).
Відкрий термінал у теці, де лежить main.py:

```powershell
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python main.py
```

## Робота з програмою

1. «Відкрити зображення» — вибрати PNG, JPEG, BMP або звичайний TIFF.
2. «1. Розділити H&E» — отримати канали H (гематоксилін) і E (еозин).
3. «2. Знайти кандидатів» — виконати Оцу, відкриття й відбір компонентів.
4. «3. Watershed» — автоматично розділити області за картою відстаней.
5. «4. Текстура LBP» — карта кодів, гістограма й ознаки текстури.
6. Вибери у випадному списку потрібну маску, накладання чи LBP-гістограму.
7. Перевір кількості до/після, площі, периметри й округлість у таблиці.
8. «Зберегти результати» — експорт поточної стадії та порівняння.

У каналах H/E темніше означає більше барвника. У масках біле означає об’єкт,
чорне — фон. На вкладці «Об’єкти» зелені межі й жовті номери накладені
на оригінал. Номери відповідають CSV й числовій карті міток.
Для дрібних об’єктів номери можуть накладатися; точні відомості є в таблиці.

Усі алгоритми працюють у вихідній роздільності. Зменшується лише екранна копія.
Для TIFF читається перший кадр. SVS і цілі цифрові препарати не підтримуються.
Скасування вибору файлу або пошкоджений файл не видаляють попередні результати.
Новий успішно відкритий файл скидає результати попереднього.
Повторне розділення H&E також скидає попередню сегментацію.
Кнопки блокуються під час обчислень і експорту, операції виконуються у фоні.

До Watershed рахуємо зв’язні області, після — відібрані басейни.
Це кандидати в ядра: пігменти й інші структури можуть бути хибними
кандидатами, а маркери можуть надмірно ділити або пропускати центри.
Оцінка на реальних еталонних масках ще попереду.

## Конфігурація

Параметри змінюй у config.json й перезапускай програму.
Інший файл: `python main.py --config path/to/config.json`.

| Параметр | Значення | Що змінює |
|---|---|---|
| preview_width / preview_height | 980 / 540 | Максимальний розмір екранної копії |
| max_pixels | 25000000 | Ліміт пікселів одного файла |
| stains.hematoxylin / eosin | RGB-вектори | Початковий профіль барвників |
| stains.white_level | 255 | Білий рівень для оптичної густини |
| stains.block_rows | 128 | Висота смуги обчислення H/E |
| segmentation.threshold_floor | 15 | Нижня межа порога сили H (0–254) |
| segmentation.opening_radius | 1 | Радіус диска; 0 вимикає очищення |
| segmentation.min_area | 30 | Мінімальна площа кандидата, пікселі² |
| segmentation.max_area | 0 | Максимальна площа; 0 — без верхньої межі |
| segmentation.connectivity | 8 | Зв’язність: 4 або 8 сусідів |
| segmentation.exclude_border | false | true відкидає області на краю кадру |
| watershed.min_peak_distance | 8.0 | Мінімальний інтервал між піками в пікселях |
| watershed.min_peak_height | 2.0 | Мінімальна висота піка EDT |
| watershed.relative_peak_height | 0.35 | Мінімальна частка максимуму своєї компоненти |
| measurements.pixel_size_um | null | Відома калібровка, мкм/піксель; null — невідома |
| texture.source | hematoxylin | hematoxylin або gray |
| texture.scope | whole | whole або objects |

Поріг Оцу обчислюється автоматично. Застосований поріг — максимум між ним
і threshold_floor. Параметри за замовчуванням — стартові, не підібрані під
конкретну гістологічну вибірку. Якщо дрібні ядра зникають, перевір min_area
та opening_radius. Якщо багато слабко забарвленого фону, перевір H-профіль
і threshold_floor. Розміри в пікселях залежать від збільшення сканера.

## Експорт

Кожен запуск збереження створює нову теку histology_* у вибраному місці.
Навіть до сегментації можна зберегти канали:

- hematoxylin.png, eosin.png — канали пропускання uint8;
- hematoxylin_od.npy, eosin_od.npy — незмасштабовані карти OD float32;
- parameters.json — джерело, розміри й використані параметри.

Після сегментації додаються:

- nuclear_strength.png — сила H: 255 мінус канал пропускання;
- raw_mask.png — поріг Оцу з нижньою межею;
- opened_mask.png — після морфологічного відкриття;
- mask.png — після відбору компонентів;
- labels.npy — int32: 0=фон, додатне число=ID кандидата;
- overlay.png — оригінал із межами та номерами;
- objects.csv — ID, площа, межі рамки, центр і ознака дотику до краю;
- у parameters.json також записуються пороги й кількість кандидатів.

CSV у UTF-8 із BOM; роздільник — кома. За потреби імпортуй його в Excel
через «Дані → З тексту/CSV». Для порожньої маски CSV містить тільки заголовок.
Координати від нуля, x_max і y_max — виключні; площа у пікселях².
Для мкм² потрібна відома калібровка pixel_size_um; без неї фізичні поля порожні.
Периметр — кількість відкритих сторін пікселів; округлість=4πA/P².
Щільність розраховується на всю площу кадру, а не тільки тканину.

Після Watershed додатково зберігаються EDT, маркери, мітки до/після,
objects_before.csv та summary.json з порівнянням. Повний опис одиниць,
параметрів і форматів: docs/WATERSHED.md.
Після помилки запису можуть залишитися часткові файли у новій теці.

## Структура та перевірки

- main.py — запуск;
- histology/config.py — параметри;
- histology/image_io.py — читання зображень;
- histology/stains.py — ручне розділення H/E;
- histology/segmentation.py — Оцу та морфологія;
- histology/components.py — компоненти зв’язності й площі;
- histology/watershed.py — EDT, автоматичні маркери та затоплення;
- histology/measurements.py — периметр, округлість, калібровка та щільність;
- histology/analysis.py — послідовність аналізу й накладання меж;
- histology/export.py — експорт;
- histology/app.py — вікно;
- tests/ — малі автотести;
- docs/ — формули, джерела й план роботи;

```powershell
.venv\Scripts\python -m unittest discover -s tests -v
```

Числові тести перевірено автоматично. Графічне вікно потрібно перевірити
на твоєму комп’ютері. На реальній гістологічній вибірці точність ще не оцінена.

Для початкової перевірки обери фрагмент 512×512 або 1024×1024: ручні
алгоритми на великих зображеннях можуть бути повільними. Кнопки під час
обчислень заблоковані, інтерфейс залишається доступним.

```powershell
.venv\Scripts\python main.py --input "tissue.png" --method all --output results
```

Для opening/watershed вхід — чорно-біла маска 0/255.
Для lbp з source=hematoxylin H/E виконується автоматично.

## Нове у частині 6

У поточній версії результати перемикаються випадним списком. Додано «Порівняти з еталоном» та «Обробити вибірку CSV».
Для порівняння потрібна справжня розмітка того самого кадру в PNG або NPY.
Без неї якість сегментації не обчислюється. PNG дає піксельні метрики,
цілочислові instance-ID NPY — також похибку кількості ядер.

```powershell
.venv\Scripts\python main.py --batch dataset.csv --output results
.venv\Scripts\python main.py --input tissue.png --method all --reference truth.npy --output results
```

Формат dataset.csv: `image,reference`; шляхи відносні до самого CSV.
Файл examples/dataset_template.csv містить тільки шаблон назв, даних немає.
Після пакетного запуску перевір batch_status.csv, metrics.csv та comparison.csv.
Метрики: Dice, IoU, precision/recall, MSE/PSNR бінарних масок, допоміжний
ssim_global та, за instance-еталоном, абсолютна й відносна похибка N.
SSIM тут глобальний, а не стандартний локальний Gaussian-window SSIM.
Правила порожніх масок, формули й інструкція: docs/EVALUATION_AND_BATCH.md.
