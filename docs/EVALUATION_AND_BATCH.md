# Частина 6: кнопки перегляду, метрики та вибірка

## Перемикання результатів

Випадний список прибрано. Результати перемикаються кнопками з фіксованим
станом натиснення: Оригінал, H, E, маски, Watershed, LBP. Кнопки
розміщуються по шість у рядок, тому всі доступні без розкриття списку.
Для екрана масштабується лише поточна картинка; алгоритми працюють
на початковому розмірі.

## Один кадр у вікні

1. Відкрий кадр, виконай H&E та пошук кандидатів.
2. За потреби запусти Watershed і LBP.
3. Натисни «Порівняти з еталоном» та вибери розмітку того самого кадру.
4. У вікні з’являться Dice й IoU. «Зберегти результати» запише повні
   evaluation.csv та evaluation.json разом із масками.

Новий кадр, повторне H&E або нова сегментація скидають старі метрики.
Зміна LBP не змінює геометрію маски, тому не скидає її оцінювання.
Після Watershed доступне оцінювання до/після. Повторний запуск Watershed
також вимагає нового порівняння. Не використовуй вихід програми як її еталон.

## Формат еталона

Розміри й просторове вирівнювання мають точно збігатися. Масштабування
еталона не виконується. Для файлів-зображень, як і для оригіналу,
враховується EXIF-орієнтація; для NPY дані вже мають бути вирівняні.

| Формат | Значення | Які оцінки доступні |
|---|---|---|
| PNG/BMP/TIFF | Бінарні 0/1 або 0/255, однакові RGB-канали | Перекриття пікселів; кількість ядер невідома |
| NPY bool | False=фон, True=об’єкт | Перекриття; кількість невідома |
| NPY integer | 0=фон, додатний ID=одне ядро | Перекриття та похибка кількості ID |

Збереження NPY виконуй з allow_pickle=False; завантаження ніколи не дозволяє
pickle. ID можуть бути не послідовними: [7,31] означають два об’єкти.
Один ID в кількох місцях усе одно означає один розмічений об’єкт.
Для кількості ядер, що торкаються, потрібні справжні instance-ID,
а не зв’язні компоненти їхньої спільної бінарної маски.

Кольорова розмітка, JPEG-маски та float-карти ймовірностей не приймаються.
Файл інтенсивності 16-bit, конвертований читачем у RGB, не є форматом
для instance-ID: для них використовуй цілочисловий NPY.
Відсутність еталона не є нульовою якістю: метрики просто не обчислюються.

## Формули й домовленості

TP — спільний передній план; FP — зайві пікселі; FN — пропущені;
TN — спільний фон.

- Dice = 2TP/(2TP+FP+FN).
- IoU = TP/(TP+FP+FN).
- Precision = TP/(TP+FP); Recall = TP/(TP+FN).
- MSE_binary = (FP+FN)/(H·W), значення масок 0/1.
- PSNR = -10log10(MSE_binary), максимальний рівень=1.
- count_absolute_error = abs(Npred-Nref).
- count_relative_error = abs(Npred-Nref)/Nref, якщо Nref>0.

Порожня пара: Dice=IoU=1. За відсутності передбаченого переднього плану
precision=null; за відсутності еталонного — recall=null. Відносна похибка
кількості для нульового еталона — null; абсолютна похибка лишається.
За MSE=0 поле psnr_db=null і psnr_infinite=true (математично +∞).
Для CSV невизначені значення порожні, у JSON — null; NaN/Infinity не пишемо.

ssim_global обчислюється з глобальних середніх, population-дисперсій
та коваріації двох бінарних масок, C1=.01², C2=.03²:
((2μxμy+C1)(2cov+C2))/((μx²+μy²+C1)(varx+vary+C2)).
Це допоміжна глобальна оцінка, НЕ стандартний локальний Gaussian-window
SSIM та не заміна Dice/IoU. Порівняння RGB-оригіналу з бінарною маскою
не використовується для оцінювання сегментації.

Похибка N не є instance-F1: злиття та зайвий поділ можуть взаємно
компенсуватися в загальній кількості. Для цього проєкту зберігай також
накладання та аналізуй конкретні помилки, а не тільки середні числа.

## Пакетна обробка

Підготуй UTF-8 CSV (роздільник — кома):

```csv
image,reference
images/slide01.png,references/slide01.npy
images/slide02.png,references/slide02.png
images/slide03.png,
```

Шляхи відносні до теки самого CSV; можна вказати абсолютні.
reference необов’язковий. Шляхи з комами бери в CSV-лапки.
examples/dataset_template.csv — шаблон із вигаданими назвами, а не
зібрана вибірка: підстав власні файли. У проєкті немає реальних гістологічних
зображень або масок, завантажених автоматично.

У вікні натисни «Обробити вибірку CSV», вибери опис вибірки й теку звіту.
Запускається all: H/E → Оцу → відкриття → компоненти → Watershed → LBP.
Поточний відкритий кадр при цьому не замінюється.

Через термінал:

```powershell
.venv\Scripts\python main.py --batch dataset.csv --output results
```

За потреби можна додати --method otsu, opening або watershed, але входи
мають відповідати вибраному методу. Для stains/lbp немає сегментаційної
маски: еталон у CSV призведе до evaluation_error, хоч сам метод виконається.

Один кадр із метриками:

```powershell
.venv\Scripts\python main.py --input tissue.png --method all --reference truth.npy --output results
```

## Звіт вибірки

Кожен запуск створює batch_*; помилка одного файла не зупиняє інші.

| Файл/тека | Зміст |
|---|---|
| config.json | Знімок конфігурації запуску |
| items/ | Окремі результати кадрів, run.json і evaluation.csv/json |
| batch_status.csv | Для кожного рядка: статус, вихідна тека, час і текст помилки |
| metrics.csv | Усі оцінені кадри та стадії; тільки якщо є метрики |
| comparison.csv | Середні за стадіями й кількість визначених значень кожної метрики |
| paired_comparison.csv | Попарні різниці до/після Watershed на тих самих кадрах |
| batch_summary.json | Кількості успіхів/помилок і зведені значення |

Статуси: ok_evaluated, ok_no_reference, processing_error, evaluation_error.
Після evaluation_error результати обробки можуть бути збережені —
помилка стосується лише еталона або оцінювання. Завершення пакетної команди
означає створення звіту, а не відсутність помилок; перевір batch_status.csv.

Для all порівнюються чотири стадії: otsu (включно з threshold_floor),
opened, before_watershed, final. Для перших двох є лише піксельні метрики.
До/після Watershed додається похибка N, якщо еталон має instance-ID.
Вододіл без нульової лінії може змінити лише ID, тому Dice може лишитися
тим самим, а підрахунок — змінитися. Відбір за площею також впливає на N.

comparison.csv — macro-середні по доступних оцінених кадрах, не піксельне
micro-усереднення. Для кожної метрики наведено n. Нескінченні PSNR не
входять у mean_psnr_db; їхня кількість записується окремо. Додатково є
mean_dice_nonempty_reference, щоб порожні кадри не приховували помилки.
Порівнюй стадії на однакових кадрах; для цього є paired_comparison.csv.
У ньому додатний Dice delta — покращення, від’ємний count-error delta —
зменшення похибки кількості. Це арифметичне порівняння, не статистичний тест.

## Перевірки й наступні кроки

Тести перевіряють ручні TP/FP/FN/TN, порожні маски, одиниці PSNR,
непослідовні ID, різні розміри, відсутні файли, відсутні еталони та продовження
пакета після помилки. Це не результати на реальній гістологічній вибірці.
Графічний запуск потрібно перевірити на своєму комп’ютері.
Повний статичний аналіз, реальні експерименти, підбір параметрів на окремій
підвибірці, графіки й наукові висновки ще потрібно завершити до здачі.
Мінімум за умовами — 10 відкритих зображень; реальні джерела й ліцензії
мають бути задокументовані окремо. Пороги ТЗ не вважаються досягнутими
лише через проходження синтетичних тестів.
