# Частина 5: LBP і окремий запуск методів

## Що таке LBP

LBP описує локальну текстуру; він не визначає діагноз і не вирішує,
чи є конкретна область ядром. Реалізовано звичайний 8-бітний LBP 3×3,
без навчання, класифікатора та готових функцій комп’ютерного зору.

Для кожного внутрішнього пікселя порівнюємо 8 сусідів із центром.
Якщо сусід >= центру, біт=1, інакше 0. Кожен біт має вагу 2^k.
Порядок k=0..7 за годинниковою стрілкою: NW,N,NE,E,SE,S,SW,W.
Наприклад, одиничні біти 0,2,3,6 дають код 1+4+8+64=77.
Сусіди рівної яскравості дають 1: однорідна внутрішня область має код 255.
Нульовий код також є допустимим, якщо всі сусіди темніші за центр.

Рамку завширшки 1 піксель не обчислюємо. У ній коди записані як 0,
але ці пікселі виключені з гістограми. Саме для розрізнення рамки й
дійсного коду 0 зберігається lbp_valid_mask.png. Якщо кадр менший 3×3,
гістограма порожня, ентропія й енергія — null, без аварійного завершення.

## Джерело та область

У config.json додано:

```json
"texture": {"source": "hematoxylin", "scope": "whole"}
```

- source=hematoxylin: сила H, тобто 255 мінус канал пропускання.
  Спочатку виконай H&E. Вищий код LBP не означає більше гематоксиліну.
- source=gray: яскравість RGB за формулою round(.299R+.587G+.114B).
  У вікні можна запустити LBP без H&E. Ця допоміжна конвертація не
  зараховується як новий метод замість методів лабораторних №5–6.
- scope=whole: усі допустимі центри, включно з фоном.
- scope=objects: лише центри, що мають додатний ID у поточній сегментації;
  спочатку потрібна друга або третя кнопка. Вікна 3×3 можуть охоплювати
  фон за межею об’єкта: обмеження діє на центр, а не на всіх сусідів.

Якщо є сегментація, додатково будуються гістограми кожного об’єкта.
Мітки беруться з поточної стадії: до або після Watershed. Після зміни
сегментації попередній LBP скидається, щоб не зберігати застарілі ID.
Новий файл і повторне H&E також скидають LBP. Після зміни config.json
програму потрібно перезапустити.

Фон може домінувати в whole-гістограмі. Перед порівнянням зображень потрібно
зафіксувати джерело, scope, масштаб і процедуру сегментації. Немає
інваріантності до повороту. Порівняння >= стійке до строго зростаючих
перетворень інтенсивності без втрати порядку; квантування і шум можуть
змінити коди. Це не гарантія стійкості для будь-якого освітлення.

## Ознаки

p[k]=count[k]/sum(count).

- Ентропія: -sum(p[k]*log2(p[k])) для p[k]>0.
- Енергія: sum(p[k]^2).
- Домінантний код: код із найбільшою частотою; за нічиєї — найменший.

Це описові ознаки, а не оцінки якості виділення ядер. Не порівнюй
LBP-коди з оригінальними RGB-пікселями за MSE як доказ якості сегментації.

## Вікно

Після відкриття й H&E натисни «4. Текстура LBP». За замовчуванням scope=whole,
тому пошук кандидатів не обов’язковий. Для ознак кожного кандидата
спочатку виконай сегментацію та, за потреби, Watershed.

Замість довгого рядка вкладок тепер є список перегляду: оригінал,
H/E, маски, результати Watershed, вхід LBP, коди та гістограма.
Зберігаються лише екранна копія поточного результату й вихідні дані.
Дані не масштабуються перед аналізом.

## Файли LBP

Після «Зберегти результати» до поточної теки запуску додаються:

| Файл | Зміст |
|---|---|
| lbp_source.png | Вхідна 8-бітна яскравість для LBP |
| lbp_codes.png, lbp_codes.npy | Коди uint8 у початковому розмірі |
| lbp_valid_mask.png | Центри, враховані в загальній гістограмі |
| lbp_histogram.csv | Усі 256 кодів, count і probability |
| lbp_histogram.png | Графік абсолютних частот |
| lbp_features.json | Параметри, джерело, ознаки й гістограми кожного ID |
| lbp_objects.csv | ID, кількість центрів, ентропія, енергія, домінантний код |

CSV — кома, UTF-8 із BOM. Нульова кількість центрів означає порожні
поля ознак у CSV і null у JSON. Якщо LBP запущений без сегментації,
таблиця об’єктів містить тільки заголовок. Якщо сегментація є, ID
відповідають objects.csv і labels.npy поточного запуску.

## Окремий запуск із термінала

Без аргументів `python main.py` відкриває вікно. Для роботи без вікна
обов’язкові разом --input та --method. Команди нижче виконуються з теки,
де лежить main.py; у Windows заміни python на .venv\Scripts\python.
Файли й теки з пробілами бери в лапки.

```bash
python main.py --input tissue.png --method stains --output results
python main.py --input h_strength.png --method otsu --output results
python main.py --input mask.png --method opening --output results
python main.py --input mask.png --method watershed --output results
python main.py --input tissue.png --method lbp --output results
python main.py --input tissue.png --method all --output results
```

| method | Вхід і поведінка |
|---|---|
| stains | RGB-зображення, тільки розділення H/E |
| otsu | Зображення яскравості; RGB переводиться вручну в gray; світлий клас >t, без threshold_floor |
| opening | Строго чорно-біла маска 0/255; тільки відкриття, без відбору компонентів |
| watershed | Строго чорно-біла маска 0/255; EDT, маркери, затоплення, відбір басейнів |
| lbp | Текстура whole; H/E автоматично рахується лише для source=hematoxylin |
| all | RGB: H/E → Оцу → відкриття → компоненти → Watershed → LBP |

Для окремого otsu використай nuclear_strength.png, якщо потрібна світла
маска кандидатів у ядра; на темному H-каналі світлий клас відповідав би фону.
Для opening/watershed кольоровий оригінал відхиляється; маска 0/1 теж
відхиляється, бо білий передній план тут саме 255.

Окремий lbp зі scope=objects відхиляється з поясненням; використай all
або вікно з актуальною сегментацією. all автоматично виконує всі стадії
без ручних кроків, але не становить п’ять взаємозамінних алгоритмів:
кожен метод має свою задачу та тип виходу.

Для CLI записується run.json із параметрами, автоматичними передумовами,
розміром кадру й часом запуску з читанням/записом. Час не є метрикою якості.
Кожен запуск створює нову теку. Пакетні експерименти, Dice/IoU та порівняння
варіантів сегментації ще попереду. Повного виконання всіх умов проєкту
на цьому етапі не заявляємо.
