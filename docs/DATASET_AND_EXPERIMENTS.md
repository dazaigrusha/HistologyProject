# Частина 7: підготовка реальної вибірки, перевірки та графіки

## Поточний стан

У цьому архіві немає реальних гістологічних кадрів чи експериментальних
результатів на них. Додано інструменти для імпорту локального набору,
розбиття на незалежні групи та побудови графіків зі справжнього batch-звіту.
Числові приклади в автотестах — синтетичні, не результати на тканинах.
Випадний список інтерфейсу з попереднього виправлення збережено.

## Обраний кандидат: CryoNuSeg

Авторський репозиторій:
https://github.com/masih4/CryoNuSeg

Сторінка набору, на яку посилаються автори:
https://www.kaggle.com/datasets/ipateam/segmentation-of-nuclei-in-cryosectioned-he-images

За описом авторів це 30 H&E-фрагментів 512×512 із 10 органів, із вручну
позначеними ядрами. Публікація описує три варіанти ручної розмітки;
для експерименту потрібно зафіксувати ОДИН набір анотацій і не змішувати
його між кадрами чи запусками. Дані придатні для перевірки класичного
алгоритму; навчати нейронні мережі для цього проєкту не потрібно.

Mahbod, A., Schaefer, G., Bancher, B., Löw, C., Dorffner, G., Ecker, R.,
& Ellinger, I. (2021). CryoNuSeg: A dataset for nuclei instance segmentation
of cryosectioned H&E-stained histological images. Computers in Biology
and Medicine, 132, 104349. https://doi.org/10.1016/j.compbiomed.2021.104349

Репозиторій містить MIT-ліцензію для коду; це не підтверджує таку саму
ліцензію для зображень. Зафіксуй умови саме вибраної версії набору зі
сторінки завантаження, її номер та цитування. У цій версії архів даних
не поширюється. Стаття з відкритим доступом також не визначає автоматично
умови всіх окремих файлів набору.

Пряма спроба завантаження з Kaggle в цьому сеансі повернула HTTP 404.
Це не доводить відсутності даних на сторінці: завантаження через сайт
може мати інший маршрут. Дані не вважалися завантаженими або перевіреними.
MoNuSeg також розглянуто як альтернативу, але тут немає його XML-імпортера.

## Як підключити архів після завантаження

1. Розпакуй набір локально, наприклад у data/raw/cryonuseg.
2. Знайди теку кольорових тканинних кадрів і теку INSTANCE-масок.
3. Перевір на кількох файлах: маска має 2D-цілі значення, 0=фон,
   різні ядра=різні ID; її розмір збігається з кадром.
4. Не обирай binary masks, border masks або distance maps замість ID.
   Бінарний файл формально може виглядати як один ID; імпортер не може
   визначити справжній зміст анотації лише з чисел. Формат задає користувач.

Приклад команди (замінюй назви тек на фактичні в архіві):

```powershell
.venv\Scripts\python tools/prepare_dataset.py --images "data/raw/cryonuseg/tissue images" --labels "data/raw/cryonuseg/label masks" --output data/prepared
```

Стандартні залежності Pillow/NumPy вже достатні. Імпорт не змінює
початкові файли: створює нову теку dataset_* у вказаній вихідній теці.
Вона містить images/*.png, references/*.npy, all.csv, calibration.csv,
test.csv та dataset.json з хешами оригіналів, ID груп і кількістю розмічених
об’єктів. Початковий розмір і значення ID зберігаються; інтерполяції немає.

Імена пар повинні збігатися без розширення. Якщо маски названі sample_mask.tif,
а кадри sample.png, додай `--mask-suffix _mask`. Дублікати базових назв,
відсутні пари, кольорові маски й невідповідні розміри відхиляються.
Кадри з EXIF-обертанням відхиляються, щоб не розсинхронізувати розмітку.
Після помилки запису у вихідній теці можуть лишитися часткові файли.

## Незалежні групи та відкладена перевірка

За замовчуванням назва оригінального файла — окрема група. Це припустимо,
лише якщо файли походять із незалежних препаратів/пацієнтів. Кілька
фрагментів одного препарату не повинні опинятися в різних частинах вибірки.
Для них задай `--group-regex` з ОДНІЄЮ групою захоплення ID препарату.
Наприклад, patient01_patch01 і patient01_patch02:

```powershell
.venv\Scripts\python tools/prepare_dataset.py --images data/raw/images --labels data/raw/masks --group-regex "^(patient[0-9]+)_" --output data/prepared
```

Розбиття детерміноване: групи впорядковуються за SHA-256 від seed та ID,
приблизно 70% йдуть до calibration, решта до test. Seed за замовчуванням 42.
Потрібні принаймні дві групи. За нерівних розмірів груп пропорція кадрів
може відрізнятися від 70/30. metadata набору має підтверджувати незалежність:
програма не може відновити пацієнта з довільного імені файла.

Не змінюй seed після перегляду якості на test. Параметри H/E, порога,
морфології, площ і маркерів підбирай лише на calibration. Фінальний config
зафіксуй у Git перед першим фінальним запуском test.

## Послідовність експерименту

1. Підготувати вибірку та перевірити dataset.json і кілька накладань анотацій.
2. Виконати кілька обґрунтованих конфігурацій на calibration.csv.
3. Зберегти кожен batch-звіт, його config.json і коротку причину зміни параметрів.
4. Вибрати одну конфігурацію на calibration, зафіксувати її комітом.
5. Один раз оцінити її на test.csv; після перегляду test її не підбирати знову.
6. Звітувати і середні, і помилки конкретних кадрів; не видаляти складні кадри.

Приклад запуску на підготовленій вибірці:

```powershell
.venv\Scripts\python main.py --batch "data/prepared/dataset_XXXX/calibration.csv" --output results/calibration
.venv\Scripts\python main.py --batch "data/prepared/dataset_XXXX/test.csv" --output results/test
```

Порівнюй однакові кадри між стадіями. Для LBP порівнюються описи текстури;
його коди не є маскою і не порівнюються з розміткою за Dice.
Навіть гарний Dice не доводить правильного розділення екземплярів —
аналізуй похибку кількості й накладання меж. Рівна кількість теж не
доводить правильного зіставлення окремих ядер.

## Графік зі звіту

Додатковий пакет потрібен тільки для графіків:

```powershell
.venv\Scripts\python -m pip install -r requirements-report.txt
.venv\Scripts\python tools/plot_comparison.py --batch "results/test/batch_XXXX"
```

Створюється comparison.png: macro Dice/IoU за стадіями та середня
абсолютна похибка кількості. Якщо instance-еталонів немає, поле похибки
кількості показує пояснення замість вигаданих нулів. Дані беруться тільки
з comparison.csv, ніякі показники не вписуються вручну.
Враховуй n, порожні еталони та статуси помилок із batch-звіту. Цей графік
є описовим і не містить довірчих інтервалів або тесту значущості.

## Що лишається до фінальної здачі

- Фактично отримати й перевірити відкриті дані, записати джерела та умови.
- Провести реальні calibration/test-запуски; досягнення порогів ТЗ поки не заявляється.
- Підготувати звіт із власними результатами та оглядом суміжних праць.
- Перевірити графічний запуск на комп’ютері виконавиці.
