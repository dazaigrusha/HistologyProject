# Частина 4: розділення дотичних ядер через Watershed

## Що робить програма

Після «2. Знайти кандидатів» натисни «3. Watershed». Програма самостійно
обчислює карту відстаней, ставить маркери й ділить маску на басейни.
Ручних кліків для позначення центрів немає. До/після показуються кількості,
накладання меж і таблиці вимірювань. Повторний запуск починається з тієї
самої відкритої маски, а не дробить попередні басейни повторно.

## Алгоритм

1. Беремо opened_mask з етапу Оцу/морфології. Відкидаємо компоненти,
   менші за min_area. Верхню межу площі та відбір за краєм поки не застосовуємо:
   велика злипла область може містити кілька допустимих ядер.
2. EDT: для кожного пікселя об’єкта обчислюємо евклідову відстань до центру
   найближчого фонового пікселя. За межами кадру — додаткова фонова рамка.
   Перетворення сепарабельне: одновимірна нижня оболонка парабол спочатку
   по рядках, потім по стовпцях, на завершення — квадратний корінь.
3. Кандидати в маркери: локальні максимуми карти в околі 3×3. Висота має
   перевищувати min_peak_height та relative_peak_height від максимуму
   своєї компоненти. Рівне зв’язне плато дає одну точку біля центру плато.
4. Піки впорядковуються за спаданням висоти, потім за y,x. Піки ближчі
   за min_peak_distance у тій самій компоненті відкидаються. Якщо всі
   піки відкинуті порогами, максимум компоненти стає резервним маркером.
5. Рельєф = -EDT. Затоплення від маркерів реалізовано через heapq:
   рівень нового пікселя = max(рівень поточного, -EDT нового).
   За рівних рівнів діє FIFO. Випадковості немає; обхід сусідів фіксований.
6. Усі пікселі вхідної маски отримують ID. Нульових розділювальних смуг
   усередині не створюємо: вододіл проходить між різними ID. Тому двійкова
   маска до/після може виглядати однаково. Різницю видно на кольорових
   мітках і накладанні меж. Не можна повторно запускати connected_components
   на labels>0 для підрахунку — це знову об’єднає сусідні басейни.
7. Кожен басейн фільтрується за min_area, max_area, exclude_border;
   його ID ущільнюється до 1..N. Вимірювання виконуються для залишених міток.

Це власна маркерна реалізація з пріоритетною чергою. Вона не є дослівним
перенесенням алгоритму Vincent–Soille і не гарантує збігу піксель-у-піксель
з OpenCV чи іншими варіантами Watershed, особливо на плато та при нічиїх.
EDT, пошук маркерів і затоплення реалізовані без готових функцій CV.

## Параметри

| Поле config.json | Стартове значення | Призначення |
|---|---:|---|
| watershed.min_peak_distance | 8.0 | Мінімальна відстань між маркерами, пікселі |
| watershed.min_peak_height | 2.0 | Мінімальна висота піка EDT, пікселі |
| watershed.relative_peak_height | 0.35 | Частка максимуму компоненти, від 0 до 1 |
| measurements.pixel_size_um | null | Мкм/піксель; лише відома калібровка |

Ці значення — початковий профіль, не параметри, підібрані на реальній вибірці.
Завелика відстань між піками зливає центри; замала може дробити одне ядро.
Слабка або нерегулярна маска дає ненадійні маркери. Якщо маска ще на етапі
Оцу пропустила ядро, Watershed його не відновить.

## Вимірювання

- Площа A — кількість пікселів басейну.
- Периметр P — кількість відкритих сторін квадратних пікселів у 4-сусідній
  сітці; враховує отвори й межі між сусідніми басейнами.
- Округлість = 4πA/P². Сітковий периметр має орієнтаційне зміщення,
  тому навіть майже круглий об’єкт не обов’язково має значення близько 1.
- Еквівалентний діаметр = sqrt(4A/π).
- Щільність = N / площа всього кадру (кандидатів/Мпіксель).
  Це не щільність на площу тканини: тканинної маски на цьому етапі немає.
- Якщо відомий s=pixel_size_um для квадратних пікселів:
  A_um²=A·s², P_um=P·s, щільність/мм²=N·10^6/(H·W·s²).
  Без калібровки фізичні величини — null у JSON і порожні поля в CSV.

До Watershed використовується той самий відбір, що в частині 3. Після
Watershed відбір застосовується до басейнів. Тому зміна кількості може
походити і від розділення, і від відбору дрібних/великих областей.
Наприклад, велика область, відкинута max_area раніше, після поділу
може дати кілька допустимих кандидатів.

## Файли експорту

Файли частини 3 зберігаються. objects.csv доповнено периметром, округлістю,
еквівалентним діаметром і фізичними одиницями. summary.json містить
середні значення та щільність; до Watershed є тільки after (поточний результат),
після Watershed є before і after.

Додатково після Watershed:

| Файл | Зміст |
|---|---|
| distance.npy | Вихідна EDT float32, відстані у пікселях |
| distance.png | EDT для перегляду, масштабована на максимум цього кадру |
| markers.npy | Точкові маркери int32 |
| markers.png | Червоні кружечки на EDT; кружечки збільшені лише для показу |
| watershed_labels.npy | Усі басейни перед відбором за площею/краєм |
| before_labels.npy | Мітки кандидатів до Watershed |
| before_overlay.png | Накладання меж до Watershed |
| objects_before.csv | Вимірювання кандидатів до Watershed |
| labels.png | Кольорові мітки кінцевих відібраних кандидатів |

labels.npy, mask.png, objects.csv, overlay.png відповідають поточній стадії:
якщо Watershed вже запущений — це його кінцевий результат.

## Перевірка та обмеження

Автотести включають EDT квадрата 5×5 і прямий перебір найближчого фону,
нічиї на плато, резервний маркер, два злиті диски, повторний запуск,
периметр квадрата й кільця, калібровку та відповідність міток рядкам CSV.
Геометричні синтетичні маски не замінюють гістологічну вибірку.
Точність виділення реальних ядер і метрики Dice/IoU ще не оцінені.

Обробка великих полів зору може бути повільною: EDT містить Python-цикли,
а затоплення з пріоритетною чергою потребує O(N log N) у загальному випадку.
Рекомендовано почати з окремих фрагментів 512×512 або 1024×1024.
Автоматичного зменшення для аналізу немає. Ліміт max_pixels не гарантує
достатнього обсягу оперативної пам’яті.
